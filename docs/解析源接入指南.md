# 把网站变成解析源：完整接入指南

> 本文以 **maxhelper.app** 逆向实战为例，总结「把一个网页解析工具站变成 ClipDownloader 云解析源」的完整方法论。
> 适用对象：任何「浏览器里粘贴链接就能免费解析」的网站（抖音/小红书/快手/微博等解析工具站）。
> 目标：让 App 内 OkHttp 直接调用该站后端 API，绕过页面，协议级接入。

---

## 0. 前置判断：什么样的网站值得接

先回答三个问题，都满足才动手：

| 判断 | 说明 |
|---|---|
| 免费 + 免登录？ | 浏览器打开页面，粘贴链接直接出结果（不强制登录） |
| 有无水印直链？ | 解析结果给无水印/原图直链（否则接了没意义） |
| 后端不是纯前端代理？ | 页面是真正调后端 API 取数据（不是把链接转给第三方服务） |

> ⚠️ 教训 1：**不要被「403」吓退**。maxhelper 初次裸调 API 全部 403（`securityDialog` / `pi_cf6332`），当时差点判定「无法接入」。实际上它是**自研加密信封协议**，不是 Cloudflare 人机挑战。先挖协议，再下结论。

---

## 1. 第一步：抓页面，找前端 JS

Next.js / Vue / React 站点，后端 API 地址藏在 JS chunk 里。

```bash
# 抓首页，列出所有 JS chunk
curl -s -L -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36" \
  https://www.maxhelper.app/ -o home.html
grep -oE 'src="/_next/static/chunks/[^"]+"' home.html | sort -u

# 解析功能页（如 /zh/douyin）有独立 chunk，也要抓
curl -s -L -A "<同上UA>" https://www.maxhelper.app/zh/douyin -o douyin.html
```

关键点：

- **功能页（解析组件）的 chunk 才是核心**：首页 chunk 多是框架代码，解析逻辑在 `/zh/douyin` 页面额外引用的 chunk（本例：`152-*.js` 是 CryptoJS、`6202-*.js` 是解析组件、`9895-*.js` 是风控配置）
- 所有 chunk 下载后统一搜关键词：

```bash
grep -oE 'https?://[^"'"'"'` ]{8,140}' *.js | sort -u          # 外部 API 域
grep -oE '"/[a-zA-Z0-9_/-]*api[a-zA-Z0-9_/-]*"' *.js | sort -u # /api/ 路径
grep -oE 'fetch\([^)]{0,120}' *.js                              # fetch 调用
grep -oE 'JSON\.stringify\([^)]{0,120}' *.js                    # 请求体
```

## 2. 第二步：逆向协议（本次实战核心）

maxhelper 的协议最终是**两步 + 加密信封**，全部从 JS 逆向出来：

### 2.1 风控配置藏在 JSON.parse 里

`9895-*.js` 里有一整段 JSON 配置，定义了整套协议：

```json
{
  "profiles": [{
    "authRoute": "auth-cf6332",                      // 鉴权接口
    "authResponseFields": {"key": "k_cf6332", "seed": "s_cf6332"},  // 鉴权响应字段
    "parseRequestFields": {"key": "k_cf6332", "payload": "p_cf6332", "iv": "i_cf6332", "version": "r_cf6332"},
    "id": "2026w02"
  }],
  "activeProfileId": "2026w02"
}
```

> 方法：搜 chunk 里的 `JSON.parse('` 大段字面量，配置往往直接内嵌。字段命名规律（`k_/s_/p_/i_/r_ + 编号`）说明是 key/seed/payload/iv/version。

### 2.2 完整请求链路

```
① POST /api/auth-cf6332
   body: {"requestURL": "分享链接", "pagePath": "/zh/douyin", "mode": "single"}
   → 200 {"k_cf6332": "<authKey>", "s_cf6332": "<authSeed>"}
   （字段名必须是 requestURL！之前试 url/share_url/link 全失败）

② AES-GCM 加密
   key = SHA-256("authKey" + ":" + "authSeed")     ← 密钥派生
   iv  = 12 字节随机
   明文 = ① 的请求参数 JSON 字符串

③ POST /api/parse
   body: {
     "version": 3,
     "k_cf6332": "<authKey>",
     "p_cf6332": "<base64(AES-GCM密文)>",
     "i_cf6332": "<base64(iv)>",
     "r_cf6332": 1
   }
   → 200，但响应也是加密的：{"_e": 1, "_d": "<base64密文>", "_i": "<base64 iv>", "_v": "1"}

④ 解密响应
   GET /api/rc?v=<_v>  →  {"_k": "<hex密钥>"}
   AES-CBC(key = hex(_k), iv = base64(_i), data = base64(_d), PKCS7) → 明文 JSON
```

### 2.3 解密后的数据结构

```json
{
  "status": 0,
  "data": {
    "title": "作品标题",
    "cover": "https://...封面图",
    "url": "https://...主视频直链（默认档，抖音实测 720p）",
    "videos": [{
      "url": "https://...视频直链（默认档）",
      "video_fullinfo": [
        {"type": "540p", "size": 524288, "url": "https://..."},
        {"type": "720p", "size": 524288, "url": "https://..."},
        {"type": "1080p", "size": 943718, "url": "https://..."},
        {"type": "超高清", "size": 10810095, "url": "https://..."}
      ]
    }],
    "pics": ["https://...图片直链1", "..."],
    "type": "video" | "image"
  }
}
```

> ⚠️ **清晰度藏在 `videos[].video_fullinfo[]`**（2026-08-22 发现）：网页端的「超高清 (10.3MB)」等下载按钮就是渲染这个数组。`videos[].url` / `data.url` 只是默认档（抖音 720p，体积约为超高清档的 1/10）。**要最高画质必须自己从 fullinfo 里挑**——type 是标签（数字高度或「超高清/原画」等中文）、size 是字节数、url 是该档直链。注意 fullinfo 仅部分平台有（抖音有；小红书等实测为空，为空回落默认 url 即可）。

> 实测四平台全通：抖音图文（视频+图）、小红书实况（实况 mp4+图）、快手图集（多图）、微博九宫格（实况 .mov 直链+多图）。

## 3. 第三步：Python 模拟验证（必做，别跳过）

封装进 App 前，先用 Python 完整跑通，确认协议行为与边界：

```bash
# 建 venv 装加密库（路径按本机实际环境调整）
python -m venv .venv
.venv/Scripts/pip install cryptography
```

验证脚本关键点（完整脚本见 `test_pc_ua/mh_parse2.py`）：

```python
opener = urllib.request.build_opener(
    urllib.request.ProxyHandler({}),        # 沙箱必须禁代理
    urllib.request.HTTPCookieProcessor()    # ⚠️ 必须共享 cookie 会话
)
```

> ⚠️ 教训 2：**auth 与 parse 必须同一 cookie 会话**。不带 cookie 共享时 parse 返回 403 `sm_cf6332`（auth_session_mismatch）；加上 `HTTPCookieProcessor` 后直接 200。App 封装时对应给 OkHttpClient 配 `cookieJar`。

> ⚠️ 教训 3：**错误码就是协议信号**。403 的 reason 是枚举：`ie_*`=信封无效、`sm_*`=会话不匹配、`pi_*`=profile 未激活、`pd_*`=解密失败。看到不同 reason 变化 = 离成功越来越近。

## 4. 第四步：封装进 CloudParser（App 侧）

改动都在 `app/src/main/java/com/clipdownloader/download/CloudParser.kt`：

### 4.1 通道循环里识别域名，走专用协议

```kotlin
val media = if (base.contains("maxhelper.app")) {
    parseViaMaxHelper(base, url, platform)   // 专用协议
} else {
    // ...通用 GET {通道}?url= 逻辑
}
```

### 4.2 专用协议实现（Android 原生加密，零额外依赖）

```kotlin
// AES-GCM（加密请求）
val key = MessageDigest.getInstance("SHA-256")
    .digest("$authKey:$authSeed".toByteArray(Charsets.UTF_8))
val iv = ByteArray(12).also { SecureRandom().nextBytes(it) }
val cipher = Cipher.getInstance("AES/GCM/NoPadding")
cipher.init(Cipher.ENCRYPT_MODE, SecretKeySpec(key, "AES"), GCMParameterSpec(128, iv))
val ct = cipher.doFinal(plain)

// AES-CBC（解密响应）
val cipher = Cipher.getInstance("AES/CBC/PKCS5Padding")   // PKCS5≈PKCS7，Android 用这个
cipher.init(Cipher.DECRYPT_MODE, SecretKeySpec(hexKey, "AES"), IvParameterSpec(iv))
```

### 4.3 提取媒体时务必带 originalUrl（Referer）

```kotlin
ParsedMedia(platform, videoUrl = v, imageUrl = ..., originalUrl = shareUrl)  // ← 关键！
```

> ⚠️ 教训 4：**解析成功 ≠ 能下载**。maxhelper 解析出的微博图片直链（`wx1.sinaimg.cn`）无 Referer 直接 403，带上分享链接作 Referer 后 200。云解析返回的每个媒体都要把 `originalUrl` 设成分享链接，否则图床/CDN 拒绝无来源请求。

### 4.4 OkHttpClient 必须配 CookieJar

```kotlin
private val client = OkHttpClient.Builder()
    .cookieJar(okhttp3.JavaNetCookieJar(java.net.CookieManager()))  // auth/parse 共享会话
    .build()
```

> ⚠️ 教训 5：**封装客户端必须与验证环境行为一致**。Python 用 `HTTPCookieProcessor` 能过，App 里 OkHttp 默认不管理 cookie → 会话丢失 403。cookie 管理、UA、TLS 指纹都算环境差异。

## 6. 教训总结（速查）

1. **403 不一定是死路**——可能是自研加密信封协议，挖 JS 配置（`JSON.parse('...')` 大段字面量）能拿到完整协议定义。
2. **字段名以 JS 反推为准**——`requestURL` 不是 `url`；试错参数名永远不如读源码来得快。
3. **会话一致性是隐形门槛**——auth 和业务请求必须共享 cookie 会话，验证脚本和 App 客户端都要配 cookie 管理。
4. **错误码即信号**——reason 枚举（ie/sm/pi/pd + 编号）的每一步变化都代表协议理解更深一层。
5. **解析成功 ≠ 能下载**——返回的每个媒体都要带 `originalUrl`（分享链接）作下载 Referer，图床/CDN 无来源一律 403。
6. **先 Python 全流程验证，再写 Kotlin**——验证环境与 App 环境行为要一致（cookie/UA/加密库语义），不一致就会出现「沙箱过、真机挂」。

## 附录：maxhelper 协议速查（2026-08-17 逆向）

- 域名：`https://www.maxhelper.app`
- 鉴权：`POST /api/auth-cf6332`，body `{requestURL, pagePath, mode}` → `{k_cf6332, s_cf6332}`
- 解析：`POST /api/parse`，信封 `{version:3, k_cf6332, p_cf6332, i_cf6332, r_cf6332:1}`
- 密钥：`GET /api/rc?v=<v>` → `{_k: hex}`（响应解密用）
- 加密：请求 AES-GCM（key=SHA-256("k:s")，iv 12B）；响应 AES-CBC（PKCS7）
- 逆向脚本：`test_pc_ua/mh_parse2.py`（单链接）、`mh_multi.py`（多平台）
