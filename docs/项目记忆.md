## 1. 项目概况

Android 原生应用（Kotlin）。剪贴板/系统分享 → 解析各平台链接 → 勾选媒体与画质 → 下载视频/图片。

| 项 | 值 |
|----|----|
| 技术栈 | AGP 8.1.0 + Kotlin 1.9.0 + compileSdk 34 + Java 17，minSdk 24 |
| 版本 | v1.3.6 / versionCode 37 |
| 签名 | `clipdownloader.jks`（RSA 2048，有效期 30 年，alias/store/key 密码均 `clipdownloader2024`） |
| keystore SHA-256 | `44C460B349414DC77DFC826E7C3678ED5085AFEB68EC3FDA467419A2232B5CC9` |
| 发布 | 打 tag `v{版本号}` 触发 GitHub Actions；工作流会校验 tag 与 `versionName` 一致 |

签名固定挂到 debug + release，**签名永不随机器变化**，保证跨版本覆盖安装。
验证 APK 签名要用 `apksigner`（`keytool -printcert -jarfile` 对 v2/v3 签名会误报「不是已签名的 jar」）。

## 2. 踩坑与教训（长期有效）

### 2.1 JVM / 编译

- **KDoc 注释里不能写 `\uXXXX` 字面量**：javac 的词法层会解析注释中的 `\u` 转义，注释里出现 `\u` 后跟字母数字会报「非法的 Unicode 转义」，导致 kapt 失败。
- **Android 的 `java.util.regex`（ICU 实现）对未转义的 `}` / `]` 比 PCRE 严格**：正则里这两个字符必须转义，例如写 `Regex(",\\s*\\}")` 而不是 `Regex(",\\s*}")`。曾因此让小红书解析抛 `PatternSyntaxException` 崩溃。
- **JSONTokener 处理裸 URL 会截断**：`JSONTokener("https://x").nextValue()` 走 `readLiteral()`，在第一个 `:` 处停止，只返回 `"https"`。正确做法是先判断 `if (!s.contains('\\')) return s`，有转义时用 `JSONTokener("\"$s\"").nextValue()`（**必须包引号**）。
- **验证脚本必须与 Kotlin 实现语义一致**：上述 bug 之所以在沙箱「验证通过」却真机失败，就是因为 Python 侧用了 `json.loads('"'+s+'"')`（包了引号），而 Kotlin 侧没包。模拟验证与真实实现的差异会直接掩盖 bug。

### 2.2 Android 平台限制

- **后台读剪贴板**：Android 10+ 起后台 App 无法读剪贴板，`OnPrimaryClipChangedListener` 在后台不回调。**本方案已放弃后台监听**，改为 App 获得输入焦点时读取（见第 8 节）。
- **Android 12+ 要求 App 拥有输入焦点**才能 `getPrimaryClip()`，所以读取逻辑放在 `onWindowFocusChanged`，而不是 `onResume`（`onResume` 时焦点未就绪，返回 null）。
- **startForeground 必须在 Manifest 声明 `foregroundServiceType`**，否则 Android 14+ 抛 `foregroundServiceType 0x... is not a subset of ... in service element`。（历史版本踩过，现已无前台服务）

### 2.3 本机沙箱环境（Windows）

- **删除文件没有回收站**：`Add-Type`（.NET）与 `New-Object -ComObject`（Shell COM）都被沙箱拦截，回收站通道不可用；safe-delete 钩子会拦 `rm -rf` 与 `shutil.rmtree`（fail-closed）。**结论：删文件等于永久删除，动手前务必二次确认**。单文件 `rm -f` 不受该钩子拦截。
- **WorkBuddy 系统代理 `127.0.0.1:3067` 会失效**：挂掉后 `curl` 直连海外站点被 CF 拦或返回空 body；用 Python `urllib` 加 `ProxyHandler({})` 显式禁代理可正常抓取。
- Git Bash 里 `yes` / `sleep` / `tee` / `unzip` 可能不存在，写脚本时避开（用 `echo y |`、Python 解压）。

### 2.4 抓取与解析通用规律

- **下载 Referer 决定成败**：图床/CDN 对无来源请求直接 403。媒体项的 `originalUrl` 必须设为**最终页面 URL**（不是短链域）。
- **CDN 可能按 UA 校验**：B站 CDN 对 Mobile UA 返回 403，Desktop UA 返回 200/206。
- **`resolveRedirect` 拿到的 finalUrl 可能被污染**：无 cookie 时 `weibo.com/uid/mid` 会 302 到 `passport.weibo.com/visitor?url=...`，此时从 finalUrl 提 ID 会先匹配到 uid（10 位）而非 mid（16 位）。
  **规矩：ID 优先从原始 URL 提取**，只有原始 URL 无 ID（短链）才在访客授权后跟随重定向；兜底正则按位数收紧（如 `(\d{16,})`）。
- **下载侧要区分「解析成功」与「能下载」**：解析出直链不等于能下，Referer / UA / cookie 任一缺失都可能 403。

### 2.5 多 dex 校验（历史方法）

曾经 minSdk<21 触发 multidex，应用代码落在 `classes4.dex`（`classes.dex` 只有引导类），因此用 `classes.dex` 搜字节串校验 APK 会漏。当前 minSdk 24，但**校验 APK 时仍应遍历所有 `*.dex`**（Python `zipfile` 读取后逐个搜字节串）。

## 4. 各平台解析要点

### 4.1 抖音 DouyinParser

- **必须移动 UA + `iesdouyin.com` 域**请求 `https://iesdouyin.com/share/video/{id}`，页面 SSR 内嵌 `_ROUTER_DATA` / `__NEXT_DATA__`（双格式兼容）。
- 数据位置：`loaderData...videoInfoRes.item_list[0]`；视频 `video.play_addr.url_list[0]`，把 `/playwm/` 替换为 `/play/` 得**无水印**地址。
- **图集走同一入口**：`/share/slides/{id}` 返回风控空壳，不能用；`share/video/{id}` 对视频和图集都返回完整数据。`ID_PATTERNS` 需包含 `video|note|slides`。
- **web API 全部要 `a_bogus` 签名**（`web/aweme/detail` 200 空 body；`iteminfo` 报 `encrypt_data_miss` 11110），PC UA 请求 share 页会被 302 到桌面壳。**不要尝试 PC UA 或裸调 API**。
- `_ROUTER_DATA` 的赋值跨行，必须用**括号配对**提取，非贪婪 `.*?</script>` 会失败。

### 4.2 快手 KuaishouParser

- **正确入口是移动端**：移动 UA 请求 `https://m.kuaishou.com/fw/photo/{photoId}`，SSR 同时内嵌视频与图集，**无需 cookie**。
- 字段：视频 `mainMvUrls[0].url`（完整 mp4 直链）；图集 `atlas.cdnList[0].cdn` + `atlas.list[]` 拼每张原图，`atlas.music` 是配乐；通用 `caption` / `userName`（仅移动端有）/ `coverUrls[0].url`。
- **桌面端 `www.kuaishou.com/short-video/{id}` 不可靠**：只对部分普通视频有 SSR 数据，图集与 `PHOTO_OTHER` 类视频返回 76KB 空壳。
- **不要走 graphql `visionVideoDetail`**：需 `did` cookie 养号，否则返回滑块验证码（`result=400002`）。
- 短链 `v.kuaishou.com/xxx` 会重定向到 `m.chenzhongtech.com/fw/photo/{id}`（含 `shareResourceType`，`PHOTO_OTHER`=图集）。

### 4.3 B站 BilibiliParser

- **只用 `durl`（`fnval=0`，完整 MP4 含音视频）**。`dash` 是音视频分离流，直接下 `dash.video.baseUrl` 会得到**无声视频**——dash 分支已删除，不要加回来。
- **CDN 按 UA 校验**：`bilivideo.com` 域名下载必须用 **Desktop UA**，Mobile UA 一律 403。
- `originalUrl`（下载 Referer）必须是 `https://www.bilibili.com/video/{bvid}`（bilibili.com 域）；用 `b23.tv` 短链域会被 CDN 拒绝。
- 无登录 cookie 时平台限 480P，属平台硬限制。
- `qn=120` 已是接口在无 cookie 下能给的最高档。

### 4.4 小红书 XiaohongshuParser

- **用 PC UA（Chrome）访问桌面页** `https://www.xiaohongshu.com/discovery/item/{noteId}`，返回**无水印原图**；移动端页面图片带水印。
- 数据在 `__INITIAL_STATE__` → `noteData.data.noteData`（本身即笔记对象）；图片字段是 `imageList[].url`（不是 `urlDefault`）；实况图 `livePhoto=true` 时视频在 `stream.h264[0].masterUrl`。
- `__INITIAL_STATE__` 是 JS 对象（含 `undefined`、尾逗号），**严格 JSON 解析会失败**：需括号配对提取 + 清洗（`:undefined`→`null`、去尾逗号）后再解析。
- **分享链接必须带 `xsec_token`** 访问详情页才有数据（App 内重定向后 URL 自带，保留即可）。
- 图片下载 Referer 必须是 `xiaohongshu.com` 域；用 `xhslink.cn` 短链域会被 `xhscdn` 全量 403。

### 4.5 微博 WeiboParser

- **无 cookie 时所有入口（weibo.com / m.weibo.cn / ajax / 老 API）都跳登录墙**，必须先模拟访客授信：
  1. `GET passport.weibo.com/visitor/genvisitor?cb=gen_callback&fp=&entry=miniblog` → JSON 取 `data.tid`
  2. `GET passport.weibo.com/visitor/visitor?a=incarnate&t={tid}&w=3&c=100&gc=&cb=cross_domain&from=weibo` → **从响应体**取 `sub` / `subp`（不在 Set-Cookie，要手动拼 `Cookie: SUB=...; SUBP=...`）
- 两端：
  - **pc**：PC UA + SUB → `weibo.com/ajax/statuses/show?id={mid}` → `pic_infos[pid]`（original=orj1080 / largest / mw2000）；实况图判 `pic_infos[pid].type == 'livephoto'`，视频直链在 `video` 字段（`.mov`，带 `Expires`/`ssig` 签名）。
  - **mobile**：移动 UA + SUB → `m.weibo.cn/detail/{mid}` → 括号配对提取 `$render_data` → `[0].status`：`pics`（large=mw2000）+ `live_photo_video_data{pid→usid}`。
- **移动 UA 调 `weibo.com/ajax` 会 403**（该接口拒绝移动 UA），移动端必须走 `m.weibo.cn` 页面。
- 设置页「微博解析端」开关（`weibo_endpoint_pc`，开=PC 端，默认）控制走哪端，仅在本地解析开启时显示。

### 4.6 国外平台

- **只有 TikTok 有本地解析**（tikwm）。YouTube 本地解析走 InnerTube + `PoTokenGenerator`。
- Instagram / Twitter-X / Facebook / Pinterest **无本地解析，依赖云端通道**。
- 已实测失败并删除的直解方案：YouTube Piped/Invidious（全超时）、Twitter vxtwitter（CF 403）、Pinterest/Instagram/Facebook og 直解（登录墙）、Cobalt 全实例（2026-08 起全要 turnstile JWT，`error.api.auth.jwt.miss`）。

## 5. 云端通道

### 5.1 通道与配置

内置 9 个通道（协议均已在 App 内逆向实现，Android 原生加密，零额外依赖）：
MaxHelper、Hellotik、DownCats、SnapAny、Oivo、SnapTok、XiaZaiTool、Kukutool、VidDown。
另有 iiiLab 内置通道，按平台勾选启用。

- **按平台独立选通道**：存储键 `platform_channel_<key>`，共 13 个键（11 个平台 + `domestic_other` / `overseas_other` 两个兜底范围）。旧的分组配置（`domestic_channel` / `tiktok_channel` / `youtube_channel` / `cloud_preferred_overseas`）会在首次读取时一次性迁移（`platform_channels_rev` = 2）。
- **云端模式失败不回落本地**。
- 内置通道定义有版本号 `builtin_channels_rev`（当前 6），升级后按**域名**把同域名的旧内置通道刷新为新定义并追加新增通道，**自定义通道原样保留**。

### 5.2 MaxHelper 协议（已完整逆向）

- `POST /api/auth-cf6332`（body `{requestURL, pagePath, mode}`，**字段名是 `requestURL`**）→ `{k_cf6332: authKey, s_cf6332: authSeed}`。
- 加密：**AES-GCM**，key = `SHA-256("authKey:authSeed")`，iv 12B 随机，明文 = 请求参数 JSON。
- `POST /api/parse`（body `{version:3, k_cf6332, p_cf6332: b64密文, i_cf6332: b64 iv, r_cf6332: 1}`）→ 响应加密 `{_e:1, _d, _i, _v}`。
- 解密：`GET /api/rc?v=_v` → `{_k: hex密钥}` → **AES-CBC**（PKCS7）→ 明文 JSON。
- **auth 与 parse 必须共享 cookie 会话**（否则 403 `sm_cf6332`）。
- 返回结构：`data.{title, cover, type, url, videos[].url, pics[]}`，全平台无水印直链。
- `pagePath` 按平台映射（`/zh/tiktok`、`/zh/instagram`、`/zh/douyin`、`/zh/bilibili`、`/zh/xiaohongshu`）。实测 TikTok ✅、Instagram ❌（站点侧返回解析失败）。

### 5.3 云解析提取规则与坑

- **必须配 CookieJar**：OkHttp 默认不管理 cookie，MaxHelper 的 auth 会话 cookie 丢失会导致 parse 403 `auth_session_mismatch`。逆向出的协议封装时，客户端行为（cookie 管理、UA、TLS）必须与验证环境一致。
- **媒体项必须带 `originalUrl`（Referer = 分享链接）**：否则新浪图床等对无来源请求 403。
- **画质在多档数组里**：MaxHelper 的 `videos[].url` 只是默认档（约 720p），最高画质在 `videos[].video_fullinfo[]`，每项 `{type(如 1080p/超高清), size(字节), url}`，抖音超高清档体积可达默认档 10 倍以上。选档逻辑见 `CloudParser.extractQualities()` + `MediaQuality`，按高度标签打分（超高清/原画/蓝光/4K→2160，2K→1440，数字 `Np`→N），size 破平手，降序取最高档。小红书等平台 fullinfo 为空时回落默认 url。
- **时长字段缺失**：MaxHelper 响应无时长 → `CloudParser.fillMissingDurations()` 用 `MediaMetadataRetriever.setDataSource(url, headers)` 远程读文件头补时长（带 Referer，b23.tv→bilibili.com 域），最多探 4 个，失败不影响解析。
- **下载栏单视频时长**：下载后探测时长除回填 `itemDurations`（多媒体网格），还要回填 `currentDuration` / `firstDuration`（单视频角标 + 历史记录用），否则单个视频不显示时长。

### 5.4 接入新解析源

完整方法论见 [解析源接入指南.md](解析源接入指南.md)：前置判断（免费/免登录/无水印直链）→ Next.js 站点挖 chunk 找 API → 逆向加密协议 → **Python 模拟验证（必做，且 cookie 会话必配）** → 封装进 `CloudParser` 专用分支。

## 6. 下载与存储

- 保存路径默认 `/storage/emulated/0/Download/ClipDownloader`（`save_path`）。
- 「保存到平台独立文件夹」（`platform_folder_enabled`，默认开）：开=按平台/博主名分文件夹，关=全部存根目录。
- `DownloadManager` 是**全局单例**（`DownloadManager.get(context)`），内部维护 `DownloadBatchState` 列表（PARSING / DOWNLOADING / COMPLETED / FAILED / CANCELLED + 字节级进度），通过 `addBatchListener` 推 UI。
- **`enqueue()` 跑在独立 `downloadScope`**（SupervisorJob + Dispatchers.IO），与 UI 生命周期解耦。曾因在 Activity scope 里 launch，导致切屏/旋转时协程被掐断、批量永远卡在「解析中」。
- 进度推送有 **200ms 节流**（`AtomicLong` compareAndSet）：字节级进度最多 5 次/秒，阶段变化（开始/完成/失败/取消）走 `notifyBatchChangedNow()` 立即推送。曾因每 64KB 全列表 `submitList` 导致 UI 卡顿。
- **下载完整性校验**：`downloadedBytes != totalBytes` 判为不完整（不能只判 `length > 0`，否则半截文件被判成功）；取消后不重试并删掉半截文件。
- `DownloadRecordStore` 以 JSON 持久化历史（`filesDir/download_records.json`），异步写盘 + 内存直读；带 **`loadFailed` 标志**，读取失败时 `persist()` 跳过写盘并把原文件备份为 `.bad`，否则一次瞬时故障后空快照会覆盖全部历史。
- 缩略图统一走 `ThumbLoader`：本地文件优先（已下载条目直接读本机文件）；远程封面按平台带 Referer / Desktop UA（微博 sinaimg 等无来源会 403）；失败后有冷却重试，避免永远卡占位图或高频重试闪屏。
- 实况图（动图）保存为「`_live.mp4` + `.jpg`」两个独立文件，不做合并；列表标注「动图」。
- 重复下载控制：`redownload_duplicates`（总开关，开=不跳过本地已存在的重复作品）+ `redownload_overwrite`（仅总开关开启时可设，开=覆盖旧文件）。

## 7. UI 与功能架构

- 底部导航**四页**：首页（粘贴解析勾选下载）、下载（实时进度 + 历史）、主页下载（博主作品批量）、设置。
- 「主页下载」支持 B站 / 抖音 / 快手 的主页地址或分享短链（`DouyinUserParser` / `KuaishouUserParser` / `BilibiliUserParser`），用 `blogger_done` 记录已下载作品 ID 做**增量去重**（上限 2000）。
- **分享面板进来不弹窗**：走首页内嵌列表 `parseAndShowInline()`，链接填进输入框后自动解析供勾选。`ShareActivity` 处理 `ACTION_SEND` / `PROCESS_TEXT`。
- **首次启动串行授权**：先弹通知权限，在权限回调里再弹媒体权限（`pendingStoragePrompt`），避免两个系统弹窗叠在一起；该标志存进 `savedInstanceState`。
- **打开 App 自动读剪贴板**（`auto_read_clipboard`，默认开）：复制链接后打开 App 自动读取并解析。已消费内容记入 `consumed_clips` 去重（上限 200），防止同一链接反复触发。
- **日志导出保留**（排查解析失败用）：`LogFile.getLogText()` + 设置页「日志」分区 `btn_export_log`，经 FileProvider 分享。`LogFile` 单后台线程写入（`filesDir/logs/app_log.txt`，上限 512KB 自动截断），曾经同步写 + 写满重写整个文件把主线程拖死。
- **版本号动态显示**：设置页底部读 `BuildConfig.VERSION_NAME`（`build.gradle` 需 `buildConfig true`，AGP 8 默认不生成）。
- `PlatformParser` 只按**平台域名 URL** 识别平台，不做「抖音/快手」等纯中文字样匹配——否则复制含平台名的普通文本会误触发下载。文本以时间戳开头（日志格式）直接返回 null。
- 微博/抖音等平台首字 `mid` 等 ID 提取、短链重定向等细节见第 4 节。

## 9. 已废弃结论（勿被旧记录误导）

以下内容在旧工作记录中出现过，但**已被后续重构移除或推翻**：

| 旧记录 | 现状 |
|--------|------|
| `canKeepAsMotionJpeg` / `videoToMotionPhoto` / `getMotionPhotoMaxDurationMs`；「动态照片双向智能处理」 | **从未实现**。`MotionPhotoUtils.pack()` 可合成单文件 Motion Photo 但**当前无调用方**（实况图改双文件保存） |
| `ClipboardService` / `ClipboardAccessibilityService` / `ClipboardTileService` / `BootReceiver` / Quick Settings Tile / 开机自启 / 前台服务保活 / 电池优化白名单 | **全部已移除**。无任何后台监听；Manifest 中无 service / receiver |
| 底部导航三页 | 已是**四页**（新增「主页下载」） |
| 画质切换（`Quality` 枚举、`AppSettings.kt`、设置页「默认画质」） | **已删除**，改为解析后按本次可用档位用滑块选（`MediaQuality`），默认最高档 |
| 平台 Cookie 管理（`CookieLoginActivity`、`getPlatformCookie`） | **已删除**。解析器不再接受 cookie 参数（内部的会话 cookie 如 ttwid / webId / 访客 SUB / MaxHelper 会话属协议必需，保留） |
| 国内/国外两个解析开关 + 各自首选通道 | 已被**按平台选通道**取代；`cloud_preferred_overseas` 仅作为迁移来源 |
| Cobalt / TikWM 兜底 / DouyinWTF / og 直解 / Piped / Invidious / vxtwitter | 实测失败，**已删除** |
| `bestQualityUrl()`、`COVER_DUP_PLATFORMS`（封面重复丢弃仅限抖音/B站/快手） | 已在后续重构中移除，选档逻辑改为 `extractQualities()` + `MediaQuality`；提取时不再按平台丢弃封面 |
| 项目根 `app-debug.apk` 作为交付物 | 现在由 **CI 发版**；根目录 APK 只是手动构建残留，已 `*.apk` 忽略 |
| 项目缺 `.gitignore` | **已补齐**（含 `.gradle/`、`app/build/`、`local.properties`、`*.apk`） |
| 请求「打开时自动下载」 | 实际行为是自动**解析并填入**首页供勾选，文案已统一 |
